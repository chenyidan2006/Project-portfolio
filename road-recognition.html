CRAIC / 竞赛小车系统联调

让小车沿赛道跑起来，
让识别结果变成车辆动作。

这是我参与的城市道路识别比赛项目。我们的主要工作是把已有的小车平台、视觉模型和控制程序接起来，通过相机配置、ROS 通信、巡线参数与动作时长调整，让小车完成赛道任务。

ROS / PythonOpenCV / TensorRTDeepStream / YOLOPID / 实车联调

代码如何驱动车辆

  1. 相机 → 分割图
    detect_line3.py 从 USB 相机读取图像，裁去顶部部分画面、在方形画布底部放置图像并缩放到 256×256，再调用 TensorRT 推理。当前分支设置 using_trt=1，并指定 5 类输出形状。
  2. 分割图 → 巡线偏差
    get_angle 选取分割图的下部区域，保留左右两侧；find_line_fit 用滑动窗口收集像素并进行二次曲线拟合。程序分别处理双线、单线和缺线情形，发布 /vtherror_topic。
  3. 偏差 → 巡线转向
    vth2ros.py 订阅偏差，通过 PID.py 计算角速度；控制器包含误差死区和积分限幅，输出再受最大角速度限制，发布到 /cmd_vel_1。
  4. 目标与赛段 → 最终动作
    DeepStream 的 YOLO 解析代码发布目标类别、面积与中心点；velpub51.py 结合这些消息、深度数据和阶段标志，切换巡线、停车、限速与转弯等行为，最终输出 /cmd_vel。

系统采用“视觉反馈巡线 + 按时间执行的赛段动作”。部分环岛、转弯与变道操作直接指定线速度、角速度和持续时间，需要结合赛道和车辆状态反复调试。

把链路接通的细节

先确认相机帧，再检查感知结果

“修bug”版本比其他快照增加了 result 目录创建、启动帧检查和循环读帧失败时跳过处理，避免直接对空图像做颜色转换。相机取流、图像预处理、分割输出与控制输出需要分段检查。

巡线参数依赖摄像头和赛道

代码里有裁剪区域、左右偏移、中心基准、灵敏度和单线跟踪分支。调整这些量会改变车辆相对车道的位置；PID 系数与最大角速度还可由 launch 文件覆盖，因此不能仅凭 Python 默认值描述最终实车配置。

交通识别需要接上行为逻辑

YOLO 解析器中可见置信度、目标面积与类别优先处理；行为节点里可见行人锁定、目标消失延迟释放，以及按目标类别和深度条件触发后续动作。它们说明识别结果怎样参与比赛流程，而非只有屏幕上的检测框。

巡线反馈与定时动作一起工作

move_action 有指定角速度、沿用最新巡线角速度等模式。直线段与部分赛段利用巡线反馈，部分动作依赖设定时长；现场调试需要同时看摄像头、车速、转向和动作持续时间。

我的参与与项目定位

我参与团队的小车运行与调试，重点是把感知和控制流程接通、根据实车表现调整运行配置。本页按代码说明团队系统的实现链路，个人参与以系统运行与联调为重点。

这段经历让我练习在既有平台上定位问题、理解模块接口和完成联调：将取流、推理、话题与车辆动作逐段核对，再观察实车表现。

验证范围

本页依据本地“7.13”“市赛结束”“修bug”等代码快照、ROS launch 文件与 DeepStream 解析代码整理。各版本不能混作一份最终运行工程；代码配置与动作分支不等于每种情形均已实测通过。

当前审阅快照的透视变换调用被注释，不列为启用功能；控制节点配置的 50 Hz 不等于模型 FPS。完整环境、模型与最终比赛版本仍需整理后才能复现。
