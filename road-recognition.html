我的工作

U-Net 训练调参与车道跟踪参数调整

参赛技术报告第 4.5.2 节将我列为队长，工作分工为 U-Net 架构训练、调参，以及 detectline 参数调整。我的工作重点是车道线识别与跟踪，使视觉结果能够用于小车沿道路行驶。

团队其他成员分别承担 YOLOv5 交通标志识别训练、PID 参数调整，以及识别程序和动作延时参数调整。这里将个人职责与团队系统分开，不把全部感知和控制开发归为个人贡献。

系统怎样工作

图像感知 → 行驶决策 → 车辆控制

根据参赛技术报告，系统结合车道线识别与交通标志检测：通过道路图像获得车道位置和交通标志信息，再输出行驶、转向、停车等动作。报告涉及 ROS、Jetson 平台、U-Net、YOLOv5 与 PID 控制。

本页先记录材料可支持的系统结构与分工；不公开训练权重、私人联系方式或整份报告，也不把报告中的优化设想、单次测试现象包装为已经复现的精度与速度指标。

代码如何连接

  1. 图像与分割
    detect_line3.py 调用 U-Net / TensorRT 相关模块，处理车道线图像。
  2. 几何与误差
    滑动窗口提取左右车道像素，计算跟踪偏差并通过 ROS 话题传递。
  3. 跟踪控制
    vth2ros.py 订阅 /vtherror_topic，以 PID 计算角速度，输出 /cmd_vel_1。
  4. 行驶决策
    velpub51.py 结合跟踪结果与交通目标信息，发布 /cmd_vel，控制停车、限速与转向等行为。

这张链路说明依据本地历史快照；其中 PID、交通标志检测和行为控制属于团队系统。我的已确认职责为 U-Net 训练调参与感知参数调整。

可展开的技术细节

从分割掩膜到车道跟踪

分割结果仍需经过几何变换与车道像素提取。滑动窗口的层数、横向宽度和有效像素阈值会影响噪声容忍度、弯道适应性与丢线情况，这也是实车参数标定的重点。

版本差异必须说明

参赛报告记录过 nwindows=9、margin=80、minpix=50；本地“7.13有30%满分率”快照中 find_line_fit 的函数默认值为 4、20、100。函数默认值也可能被调用处覆盖，不能把这些数字直接称为最终比赛配置。

控制频率与推理帧率分开

vth2ros.py 设置 50 Hz 循环、PID 采样间隔 0.02 s 与角速度限幅；这些是代码配置，不等于相机帧率、模型推理速度或实测闭环频率。目录名中的“30%满分率”缺少试验次数与日志，暂不作为成果指标。
