# IC 方向面试准备

## 30 秒自我介绍草稿

我是北京工业大学的陈一丹，希望向 IC 设计方向发展。已经学过 C 语言、数据结构与算法、数字电路、电子电路和固体电子学等课程，本学期在修数字系统设计、微控制器、信号与系统、电子线路与原理，并开始学习 Verilog、SystemVerilog 和 FPGA。此前我做过 SMI 血管参数测量系统和城市道路识别小车：前者主要负责 App 前后端、ESP32 与服务器通信及算法重训练优化；后者担任队长，负责 U-Net 训练调参与视觉感知参数标定，团队获得全国总决赛三等奖。我希望把已有的接口、数据链路和系统调试经验，逐步转化为数字电路设计与验证能力。

## 简历项目表述草稿

**SMI 血管参数测量系统｜前后端、设备通信与算法工程化**

围绕激光自混合干涉测量原型，负责 App 全部前后端、ESP32 到服务器的数据通信及算法重训练与优化，连接采集、上传、推理、存储与结果回看流程。团队获光电设计竞赛华北区一等奖，国创项目进行中。

**城市道路识别小车｜队长，U-Net 训练与感知参数标定**

负责车道线分割模型训练调参与 detect_line3.py 感知参数标定，结合滑动窗口和车道几何处理参与实车跟踪调试。团队获第二十八届中国机器人及人工智能大赛全国总决赛机器人应用赛（城市道路识别）三等奖。

投递前请按本人可解释的实际工作审阅；尚无原始日志支持的性能数字不添加。

## 技术追问准备

| 问题 | 回答应包含的证据 | 当前要补充的材料 |
| --- | --- | --- |
| 你亲自修改了什么？ | 文件、函数、修改前后现象与团队分工 | 本人提交记录或代码 diff |
| 40 kHz、16 bit 怎样估算带宽？ | 80,000 B/s；串口还需要帧与协议开销 | 固件配置、分帧与有效吞吐日志 |
| 数据不完整时如何定位？ | 采集端、串口、缓冲、上传、服务器逐段比对 | 字节计数、时间戳、校验与日志 |
| U-Net 为什么适合这里？ | 输入输出、标注方式、损失、训练/验证划分 | 实际训练脚本与曲线；不背未经核实的 Dice Loss 声明 |
| 滑动窗口三个参数有什么作用？ | 层数、横向范围、有效像素阈值；结合反光与丢线案例 | 固定场景对比与失败图像 |
| 为什么不直接说系统跑到 50 FPS？ | 50 Hz 是控制循环配置；感知和通信另有延迟 | 分节点耗时与闭环日志 |
| 软件阶段标志与 RTL FSM 有何区别？ | RTL 同时受时钟、复位、并发与时序约束 | 完成后提供本人 RTL 状态机和波形 |

## 回答转向 IC 的动机

可以说明：系统项目让我开始关注数据如何被采集、缓存与传输，希望进一步理解这些功能在数字电路中的实现，因此开始学习 HDL 与 FPGA，并准备从 UART 和 FIFO 做起。动机应以本人真实兴趣为准。

暂不将“ROS 多节点”称为硬件流水线，不将 ESP32 开发称为 IC 设计，不将 TensorRT 部署称为自研加速器，不把团队获奖写成个人独立完成全部模块。
